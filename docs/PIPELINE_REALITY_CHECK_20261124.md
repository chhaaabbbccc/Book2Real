## 2. S1 质量门：指标 PASS ≠ 画面对

仓库里已有 `skills/living-picturebook/scripts/prepare_from_book.py`，它把
`books/<id>` 转成 S1 四件套，本地用 RapidOCR 框 + 笔画掩膜 + OpenCV Navier-Stokes（NS）修补，
不联网、不花钱。本次对 cn01 实跑：

```
[prepare] cn01: 12 页, PASS 12, FAIL 0
  p02  1400x787  residual=0  ssim=1.0000  intrusion=0  PASS
  ...
```

但打开 `.tmp/clean_cn01/p02/clean_keyframe.png` 可以看到：

- 左侧两个孩子的脸、头发、身体被涂成大片竖向模糊色块；
- 右侧三块小图的人物和积木被整块抹掉/糊死；
- 页面底部导读栏和页码被抹成白条。

原因不是“偶发”，而是这条本地 S1 的结构性限制：

1. `non_edited_ssim=1.0000` 只证明**掩膜外**没动；掩膜内被 OpenCV NS 大面积涂抹，指标看不见。
2. `protected_zone_intrusion_px=0` 依赖保护区分割；这条本地路径没有 Grounded-SAM/Depth
   Anything，保护带没有真正覆盖角色五官和手，涂坏了也不会报。
3. 水印横跨角色脸和身体，OCR 框 + NS 只能“抹平”，不能按原画纹理补全；S1 skill 明确
   要求复杂结构边缘用 LaMa / Flux.1 Fill，而不是 NS 这类传统 inpaint。
4. `prepare_from_book` 默认还会把 2:1 跨页补边成 16:9；这违反 S1 铁律“输出尺寸/画幅
   与原图 100% 一致”，只是为了让下游 16:9 预检通过。

**结论：这条本地 S1 路径现在只能证明“管线能跑”，不能证明“关键帧可交付”。**
在 S1 修好之前，任何全本 Seedance 生成都会把涂坏的关键帧放大成视频，钱花了也交不了。

- S1 是大头：按 S1 skill 的 GPU 全流程 3–8 分钟/页，120 页约 **6–16 小时**；

  约 40–100 小时，不建议。**

## 5. 正确架构（新方案怎么嵌）

之前方案的问题，不是“S2/S3 代码不好”，而是把四个不同层次混成了一条：

1. **把 2.5D 本地电影当交付**：`book2real/storyfilm.py` 是程序化运镜，不是 Seedance
   生成，官方明确不得提交；它只能作为阅读器里的一路预览。
2. **跳过 S1 直接拿 `reader/art` 生成**：图上还有水印/正文，QC 必然失败；`reader/art`
   是阅读器的切图，不是 S1 的整页关键帧。
3. **把本地 OpenCV NS 去字当成 S1 PASS**：指标只锁掩膜外，掩膜内涂坏角色也报 PASS；
   没有视觉复核门，等于把坏关键帧送进 S3。
4. **用配置估值当账单**：0.40 元/条 vs 实际 5.00 元/条，导致预算和“全本 130 元”的
   结论完全失真。
5. **ASR/TTS 没有接 2s 实时链路**：Book2Real 里旧的 ASR/TTS 是离线/低配路径；
   已验证 2s 首音的是另一个包 `paperbook-backend`（MiniMax TTS/ASR 流式 + 子句切分 +
   首音保险），应该作为独立服务嵌进来，而不是在 Book2Real 里重写。

正确的分层：

```
S0 页准备：PDF/扫描页 → 单页（跨页从中缝裁开）→ 统一画幅
S1 去字补全：真 LaMa/Flux Fill 或云端图像编辑 → 掩膜外像素锁定 → 人工视觉复核
S2 分镜：scene_plan.json（段/首尾帧/转场/时长）
S3 生成：Seedance 图生视频 → QC → 返修 → concat → final_movie.mp4
   ↓
播放层：final_movie + page_timeline.json（视频内检索）
语音层：paperbook-backend（MiniMax ASR/TTS，2s 首音）→ 意图路由 → 画面定位
触控层：book.json spots + 播放器命中区
前端：一个页面同时承载播放、语音问答、触控、字幕
```

**在没有修好 S1 之前，不要跑全本 S3。** 先做一张干净关键帧 + 一段 5s 的验证
（¥5），确认 `first_frame.ssim`、`text_zero_check`、`watermark_check` 都过，再放大到一本，
最后才谈 6 本。

## 6. 下一步（按顺序）

1. **修 S1**：接入 LaMa / Flux.1 Fill（或云端图像编辑），保留像素回贴；给
   `prepare_from_book` 加“角色/手/脸保护带”与人工视觉门；现在的 NS 结果禁止进 S3。
2. **单段干净验证**：用修好的 S1 出一张关键帧，跑 1 段 5s 480p（¥5），检查 QC 三项；
   这一步通过之前，不跑整本。
3. **一本 Demo**：优先 cn01（12 页 / 120s / 480p 约 ¥120–140），跑通“S1→S2→S3→concat→
   旁白→QC 报告”。
4. **再评估 6 本**：按实测单价和余额决定是否充值/申请额度；不要用旧 130 元估算报预算。
5. **接语音**：把 `paperbook-backend` 的 MiniMax ASR/TTS 流式服务接到播放器，按
   `docs/INTEGRATION.md` 的 WS 契约，验收“说话结束→首音 <2s”。
6. **视频内检索/触控**：用 `page_timeline.json` 做页↔时间码，用 `book.json` spots 做
   命中区；问答答案必须绑定当前播放页，不能再用本地 2.5D 片的文本检索冒充。
7. **前端与两份提交文档**：等链路稳定后再改，避免把“已跑通”写成假事实。
